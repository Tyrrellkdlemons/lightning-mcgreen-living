R3: responsive refresh using original gingerbread/green-lightning identity. R4: authenticated editor photo upload, persistent Blobs, real serving URL, public gallery and responsive CDN delivery. Root integrator and three bounded Codex workers were used for UI, geography, photo implementation/research and independent review. ## Decisions

The original green bolt, cream/chocolate palette and gingerbread illustration remain. The home now starts with city search, clear rental/car/work paths, state discovery, planning and housing support. The previous global background loaded nine multi-megabyte images; one original illustration now uses Next's image pipeline on the homepage. No framework migration.

Guide coverage is distinct from inventory. Intake accepts all 58 CA and 15 AZ counties, requires state, and uses coordinates as a sanity check rather than precise border proof. The ranked workbook is unchanged. No new property stock, prices or bed availability were invented for guides.

Photo functions retain existing owner-secret authentication, fail closed, bound uploads, check types/signatures and required credit/alt/rights consent, use immutable keys and retry safety. Preview stores use trusted Netlify deploy context. No secret is in local storage, source, URL or reports.

The prior pasted prompt demanded new Decap Git Gateway. Current official documentation marks Git Gateway deprecated, so that dependency was not introduced. Identity is supported but unnecessary for the existing owner workflow. A supported GitHub-backed content editor is integrated for places and supplemental listing records; it requires owner OAuth configuration before authenticated publication can be verified. Contracted live feeds remain outside this work. Source implementation is not proof of live cloud upload operation.

## Content editing

The editor at `/admin/content/index.html` uses pinned Decap CMS 3.17.3 with the supported
GitHub backend. It edits the actual places registry through an array-preserving formatter
and supplemental rental/dealer/vehicle JSON consumed by the displayed data. Original data
and workbook records remain intact. Schema checks reject malformed records before build;
new inventory starts empty. Git media uploads are disabled; city photos use the dedicated
Blobs manager. CMS publishing controls are disabled in favor of GitHub review and merge.

Owner OAuth configuration is required before a real authenticated edit/review/publish
cycle can be accepted. No OAuth app, identity invite, account scope, Gemini key, paid feed
or production merge was created. See CONTENT_EDITOR.md for the exact supported setup.
